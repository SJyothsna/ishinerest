iShine REST API — Recent Changes

Frontend integration reference · Base URL: http://localhost:8080 · CORS: localhost:3000, localhost:5173

🆕 New Feature: Sections NEW

A new Sections layer has been added between Chapter and Question. Questions now carry a sectionId and a transient sectionName field. Sections are ordered within a chapter via displayOrder.

Section Model

FieldTypeNotes
sectionIdStringManually assigned ID
sectionNameStringRequired
displayOrderIntegerDefault 0 — use for ordering
chapterObjectNested chapter (without subject)

Section Endpoints — /sections

MethodPathDescription
GET/sectionsGet all sections
GET/sections/{sectionId}Get a section by ID
GET/sections/chapter/{chapterId}Get all sections for a chapter
POST/sectionsCreate a section
POST/sections/bulkCreate multiple sections at once
PUT/sections/{sectionId}Update a section
DELETE/sections/{sectionId}Delete a section

Updated: Questions

The Question model has several new fields. Front-end forms and display components should be updated to handle them.

New FieldTypeNotes
sectionIdStringFK to sections.sectionId (persisted)
sectionNameStringHuman-readable section name — transient, not persisted, populated at query time
hintString (TEXT)Optional hint text for the question
optionE / optionFStringMCQ now supports up to 6 options (A–F)
correctAnswersStringComma-separated for multi-correct questions
questionSetStringDefault "1" — progressive difficulty band
questionImageUrlStringOptional image URL
isCustomBooleanDefault false
visibilityStringPUBLIC / PRIVATE / SHARED
createdByUser objectLazy-loaded creator reference
usageTypeStringPractice / Test / Both

🆕 New Feature: User Management NEW

A full User CRUD + lifecycle controller is now available at /users. The UserDTO is returned for all user reads (not the raw entity).

User Endpoints — /users

MethodPathDescription
GET/usersAll users. Optional ?role=STUDENT|TEACHER|PARENT|ADMIN
GET/users/{userId}Get user by ID
GET/users/email/{email}Get user by email
GET/users/activeAll active users
GET/users/role/{role}Users by role
GET/users/role/{role}/activeActive users by role
PUT/users/{userId}/profileUpdate name + email. Body: { name, email }
PUT/users/{userId}/passwordChange password. Body: { currentPassword, newPassword } → 204
PUT/users/{userId}/deactivateDeactivate account → 204
PUT/users/{userId}/activateReactivate account → 204
POST/users/{userId}/reactivateReactivate account → 204 (alt endpoint)
DELETE/users/{userId}Soft-deactivate user → 204
DELETE/users/{userId}/hard-deletePermanently delete (inactive users only) → 204

Updated: Tests — URL Pattern Changed

⚠️ Breaking change: Test creation and management endpoints have moved from /teacher-tests to /users/{userId}/tests. This now supports both teachers and parents creating tests.

Test Management — /users/{userId}/tests

MethodPathDescription
POST/users/{userId}/testsCreate a test → 201. Body: CreateTeacherTestRequest
GET/users/{userId}/testsGet all tests created by user
GET/users/{userId}/tests/{testId}Get specific test by ID
POST/users/{userId}/tests/assignAssign test to students → 201. Body: AssignTestRequest
GET/users/{userId}/tests/{testId}/assignmentsGet all assignments for a test
DELETE/users/{userId}/tests/assignments/{assignmentId}Delete an assignment → 204

Public Test Access — /tests

MethodPathDescription
GET/tests/{testId}Get a published test (no auth required)

Updated: Parent-Student Links

Link-by-email is now preferred. The old /students endpoint is kept for backward compatibility.

MethodPathDescription
POST/parents/{parentUserId}/link-studentLink by student email → 201. Body: { studentEmail, relationshipType }
POST/parents/{parentUserId}/studentsLink by student ID (legacy). Body: { studentUserId }
DELETE/parents/{parentUserId}/students/{studentUserId}Revoke link → 204
GET/parents/{parentUserId}/studentsGet linked students (active only) → UserDTO[]
GET/parents/{parentUserId}/linksGet all links. Optional: ?status=PENDING|ACTIVE|REJECTED|REVOKED
GET/parents/students/{studentUserId}/parentsGet parents for a student
GET/parents/{parentUserId}/students/{studentUserId}/linkedCheck if actively linked → boolean

Updated: Student Notes — Image Support Added

Notes now support an optional imageUrl and color field. Two new endpoints added for image notes and bulk migration from localStorage.

MethodPathDescription

GET/students/{studentId}/notes/{chapterId}Notes for a student + chapter
GET/students/{studentId}/notes/note/{noteId}Get single note by ID
POST/students/{studentId}/notesCreate note. Body: StudentNote (title + chapterId required)
POST/students/{studentId}/notes/with-imageCreate note with image upload (multipart). Fields: image, chapterId, title?, content?, color?
POST/students/{studentId}/notes/migrateBulk import from localStorage. Body: { notes: [...] }
PUT/students/{studentId}/notes/{noteId}Update a note
DELETE/students/{studentId}/notes/{noteId}Delete a note

Integration Notes

No auth filter enforced yet: The token from /auth/login is returned but not validated by a filter on each request. Auth enforcement is planned before production.
Swagger UI: All endpoints are also documented at http://localhost:8080/swagger-ui.html — use for live testing when backend is running.
LinkStatus values: PENDING → ACTIVE / REJECTED / REVOKED
TestAssignment status values: ASSIGNED → IN_PROGRESS → COMPLETED / OVERDUE
